# 抽样复核（T1 快速准入的质量控制）

本文件是 `WORKFLOW.md` 第 10 节的执行细则。

## 1. 原则

- 不再要求每条漏洞双人独立复核。
- 高可信公报（T1）自动准入，只做三项检查；质量由**分层随机抽样 + 强制全查**控制。
- 抽样只校验：评测 SHA 是否受影响、源码位置是否真实、有无反证。不重做漏洞研究，不要求动态复现。

## 2. 抽样

- 比例：初始 **15%**（允许 10%–20%）；按实际错误率调整。
- 分层键：`repo_id`，并按语言/CWE 做二次分层报告。
- 随机种子固定（默认 `20261030`），结果可重复。
- 分配：按各层 T1 数量比例分配（最大余数法），小层不强制保底，避免总比例被抬高。
- 输出：`data/qa_reviews.jsonl`（`status=pending`）与 `reports/QA_SAMPLE_PLAN.json`。

## 3. 强制全查（不占抽样比例）

以下记录必须复核，即使未被随机抽中：

1. 版本范围冲突、backport/cherry-pick 歧义；
2. 多个 CVE/GHSA 共用同一代码位置；
3. 公报与源码明显不一致（函数/文件/版本任一对不上）；
4. `version_only` 且被用于存在性统计的条目；
5. 抽样 `fail` 项的同一 stratum 邻样本。

## 4. 结果处置

| 结果 | 处置 |
|---|---|
| `pass` | 保留原等级 |
| `fail` | 追溯同层样本；按错误性质降级 T1→T2/T3、修正位置，或升级独立复核 |
| 系统性问题 | 暂停该仓库/语言的自动准入，重跑三项检查 |

## 5. 报告

发布报告必须写明：

- 抽样比例、总体 T1 数、样本量、分层方式、随机种子；
- 强制全查数量与原因分布；
- 错误率与处置结果；
- 未复核样本的剩余风险。

## 6. 脚本

```bash
# 生成抽样计划（默认 dry-run）
python3 scripts/qa_sample.py /path/to/dataset --rate 0.15
# 写入 qa_reviews.jsonl（pending）
python3 scripts/qa_sample.py /path/to/dataset --rate 0.15 --apply
```

抽样计划不是复核结果；`status=pending` 的行在发布前必须变成 `pass` 或 `fail`。
