# v0.4.0 发布检查清单

- [ ] 每个正式评测仓库恰好一个 frozen SHA，且仓库质量通过。
- [ ] 每条正式正样本都有可信公报、明确版本关系、S1/S2 等级，以及 T1/T2 准入等级。
- [ ] T1 样本的三项 `admission_checks` 全为 true；T2 样本有定向静态核查记录。
- [ ] 正式位置 permalink 包含目标 SHA，不使用可变分支链接；`version_only` 条目已单独标注并披露。
- [ ] CVE/CWE/CVSS/修复信息均有来源；缺失或冲突值不由模型补造。
- [ ] S3/unknown/possible_affected 不进入 Known Recall 分母，并在覆盖报告中披露。
- [ ] 无需本地 PoC、编译、动态红绿测试或穷尽所有 fix commit。
- [ ] 不再要求逐条双人复核；T1 已按 10%–20% 完成分层抽样复核，强制全查项已全部复核。
- [ ] 抽样 `fail` 项已追溯同层样本并完成降级/修正；发布报告写明抽样比例、样本量和错误率。
- [ ] 只向被测 Agent 暴露固定 SHA 源码，不暴露 `.git`、公告、修复 Diff 或 Ground Truth。
- [ ] 已知漏洞 Recall 分存在性与源码定位两个口径；函数/行定位、CWE、严重程度、T1/T2 分层分别统计；未决发现不直接算 FP。
- [ ] 选择性迁移报告显示源数据未修改、迁入/排除数量可对账；tier 回溯标注有独立 before/after 哈希报告。
- [ ] 费用日志与硬预算机制状态如实报告；汇总脚本不能冒充实时熔断。
