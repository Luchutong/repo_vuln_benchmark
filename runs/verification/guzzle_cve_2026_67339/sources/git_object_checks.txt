    315      foreach ($values as $value) {
    ...
    320          $conf[\CURLOPT_HTTPHEADER][] = "$name;";

  $ grep -n "Proxy-Authorization\|PROXYHEADER\|HEADEROPT" 7.4.4 -- src
    (no match)
  i.e. the cURL handlers at this version have no special handling for
  Proxy-Authorization at all: a first-class Proxy-Authorization header stays in
  CURLOPT_HTTPHEADER. libcurl defaults to CURLHEADER_UNIFIED, so those lines are
  sent to the origin server as well, exactly the disclosure the advisory
  describes ("put every first-class request header in cURL's origin header
  list"; the advisory's own "no proxy-only channel available" paragraph covers
  this state). The stream handler only adds Proxy-Authorization to the
  proxy request when URL userinfo is parsed (StreamHandler.php:433) and does
  not remove a first-class header from the origin-bound list.
