Vulnerable code at the snapshot (v3.20.1):
  UnknownFieldSchema.mergeOneFieldFrom (line 82) handles WireFormat.WIRETYPE_START_GROUP
  at lines 98-105 and calls mergeFrom(subFields, reader) at line 101 with no recursion
  depth parameter or limit. mergeFrom (lines 114-121) loops mergeOneFieldFrom. The class
  declares no recursion limit and no DEFAULT_RECURSION_LIMIT.
  MessageSchema.mergeFromHelper calls unknownFieldSchema.mergeOneFieldFrom at line 3909
  (the other call sites are lines 4311 and 4327), which is how an unknown group in a
  parsed message reaches the recursive path. MessageSchema.mergeFrom (line 3851) is the
  public entry point used by the generated message parsers.
  skipField is abstract on CodedInputStream; the group branch cited at 662-666 belongs
  to the nested CodedInputStream.ArrayDecoder implementation (it repeats at 1378 and
  2146), and ArrayDecoders has its own recursive group paths. In 3.20.1 none of them
  checks recursion depth; the same fix adds checkRecursionLimit()/++recursionDepth
  around the ArrayDecoder skipField/skipMessage implementations (CodedInputStream
  lines 226-240 and 246-260 in the fixed tree) and depth checks in ArrayDecoders.

Fixed code at v3.25.5:
  UnknownFieldSchema declares DEFAULT_RECURSION_LIMIT = 100 (line 16) and a static
  recursionLimit (line 19). mergeOneFieldFrom takes currentDepth; the START_GROUP case
  increments it, throws InvalidProtocolBufferException.recursionLimitExceeded() when
  currentDepth >= recursionLimit (lines 84-89) and only then calls
  mergeFrom(subFields, reader, currentDepth). MessageSchema passes currentDepth 0 at
  the three call sites.
