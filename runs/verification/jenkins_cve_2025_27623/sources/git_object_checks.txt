  with a CONFIGURE check: callers with CONFIGURE get the unredacted XML, everyone else
  has it serialized to a ByteArrayOutputStream and passed through
  ExtendedReadRedaction.applyAll(xml) before being written. GetViewCommand gets the same
  branch around view.writeXml. The patch also adds PasswordTest.testViewSecrets
  (@Issue("SECURITY-3496")), which asserts that a ViewPropertySecret is redacted to
  <secret>********</secret> for a user with View/Read but not CONFIGURE, over both the
  REST config.xml URL and the get-view CLI command.
