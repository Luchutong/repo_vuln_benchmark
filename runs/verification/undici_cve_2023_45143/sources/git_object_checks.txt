The patch adds two deletions inside the existing cross-origin branch:
  request.headersList.delete('cookie')
  request.headersList.delete('host')
next to the pre-existing request.headersList.delete('authorization'), plus a new
test/fetch/redirect-cross-origin-header.js that asserts server1 receives neither
cookie nor authorization after a cross-origin redirect.

Forbidden-header handling at the snapshot: lib/fetch/headers.js contains the comment
"Note: undici does not implement forbidden header names" (lines 232, 275 and 374),
so a Cookie header set through RequestInit.headers is kept in the header list rather
than being dropped as a forbidden request header. That is why the missing delete()
in httpRedirectFetch is reachable in Node.js.

Duplicate check in the dataset at this snapshot: the already-promoted
CVE-2023-23936 (lib/fetch/index.js header injection via CRLF in the path) and
CVE-2023-24807 (lib/fetch/multipart.js filename handling) are different defects
fixed in v5.19.1. This candidate is CVE-2023-45143, the Cookie/Host leak on
cross-origin redirect, fixed in v5.26.2 by e041de3.
