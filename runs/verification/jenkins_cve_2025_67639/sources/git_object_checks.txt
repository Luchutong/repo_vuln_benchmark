  The class never overrides attemptAuthentication and never consults the CrumbIssuer,
  so the POST login endpoint accepts an authentication request without any CSRF
  token. A third-party page can therefore submit a login form on the victim's behalf
  (login CSRF): the victim's browser is logged in to the attacker's account, and
  subsequent actions the victim performs land in that account.
