Fix commit: 5290462a7ea1278a8d5c0d5b2860d4e244f997e4
  "lib: Fix overeager DTD destruction in XML_ExternalEntityParserCreate", 2022-09-20
  It adds an eight-line guard in parserCreate: when encodingName is set but
  parser->m_protocolEncodingName is NULL (copyString out of memory), and the
  caller passed a DTD (dtd != NULL), it sets parser->m_dtd = NULL before
  XML_ParserFree so the shared parent DTD is not destroyed.
  It is a commit of pull request #650 ("issue-649-fix-overeager-dtd-destruction"),
  merged by 56967f83d68d5fc750f9e66a9a76756c94c7c173 (parents 5ac71407 and
  eedc5f6d, the latter being "Changes: Document #649").
  The regression test is 43992e4ae25fc3dc0eec0cd3a29313555d56aee2
