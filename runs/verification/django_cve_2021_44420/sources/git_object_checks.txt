  `_route_to_regex` builds every endpoint regex with a trailing `$` (line 243)
  and RegexPattern.match applies it with `re.search` (line 156). In Python's re
  module `$` matches at the end of the string *or just before a trailing
  newline*, while `search` accepts a match that does not consume the whole
  string. Therefore the path '/articles/2003/\n' matches the endpoint pattern
  '^articles/(?P<year>[0-9]{4})/$' and Django resolves it, returning the
  unconsumed '\n' as the remaining path. A request fronted by an access-control
  layer that treats the trailing-newline path as different (or rejects it)
  reaches a view the layer meant to block. The same applies to developer
  patterns passed to re_path() that end in '$'.
  The fix (below) both applies fullmatch for endpoint patterns ending in '$'
  and emits \Z instead of $ from _route_to_regex. fullmatch alone is sufficient
  to reject the trailing newline, because it requires the match to consume the
  whole string.
