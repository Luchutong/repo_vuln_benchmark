Vulnerable code at 2.441:
  config-trigger.jelly (job configuration form, Build Triggers section):
    39      <!-- pseudo-trigger to configure URL to trigger builds remotely. -->
    40      <st:include page="/hudson/model/BuildAuthorizationToken/config.jelly" />
  BuildAuthorizationToken/config.jelly (blob 5603d9d8):
    37        <f:entry title="${%Authentication Token}">
    38          <f:textbox name="authToken" value="${it.authToken.token}" />
  `it.authToken` is an AbstractProject field (AbstractProject.java:228) and
  getToken() returns the stored String verbatim (BuildAuthorizationToken.java
  94-96, field `private final String token;` at 49), so the job configuration form
  renders the build authorization token in clear text in an ordinary text input.
  f:textbox is a plain <input type="text">; nothing masks or conceals the value,
  so anyone able to see the configuration page - a shoulder surfer, a screen
  share or recording, a browser extension or autofill/credential manager that
  captures form fields - can read the token, which is the only secret needed to
  trigger builds remotely.

  Both change config.jelly to:
    38          <f:password name="authToken" value="${it.authToken.encryptedToken}" />
    39          <div class="clearfix"/><!-- f:password in readOnlyMode only has a span, not a div, so the following text would be on the same line as "****" -->
  The control is now a password control fed with the encrypted Secret rather than
  the plaintext String. At 2.441, lib/form/password.jelly renders readOnlyMode value
  as "****" (line 67) and otherwise resolves the value through
  h.getPasswordValue (line 76) with hidingPasswordFields enabled by default
  (Functions.java 418-421); getPasswordValue masks with "********" when the
  current user lacks Item/CONFIGURE (Functions.java 2150-2163) and otherwise
  returns the Secret's encrypted value (2166-2168), so the plaintext is no longer
  placed in the page.
  File blob: config.jelly is 97b16ee0 at both fix commits and at both release tags.
  Regression coverage: BuildAuthorizationTokenMigrationTest (added by the same
  commit) exercises the config.xml storage/redaction side; it asserts the clear
  <authToken> value is replaced by the encrypted value and that GET config.xml
  returns <authToken>********</authToken> for a user without CONFIGURE. It does
  not drive the configuration form's password control itself.
